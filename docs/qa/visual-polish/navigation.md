# Navigation visual cleanup

The baseline is the working tree received for this task, including the existing compact navigation. The primary reviewer also captured [the baseline open Boards menu](before/chromium-light-720-boards.png) from the preserved earlier QA build. Historical evidence is preserved in [the earlier review](../compact-navigation/README.md).

| Finding | Surface and reproduction state | Before evidence | Fix | After evidence and result |
| --- | --- | --- | --- | --- |
| NAV-01 | Boards, My home and Shared space rows | Baseline `BoardNavigation.tsx` put labels in anonymous text nodes; `.menu-item` used `justify-content: space-between`, separating those labels from their icons. See the [baseline open Boards capture](before/chromium-light-720-boards.png). | Explicit fixed 18px icon, flexible label and optional metadata slots. | `visual-navigation.spec.ts`: label and icon measurements, screenshots for empty/populated Boards across five widths and two themes. Passed in Chromium and WebKit (2026-10-19). |
| NAV-02 | Boards, legacy explanation and empty Shared with me | Baseline reused Share panel `.share-head`/`.share-sub`, so supporting text inherited unrelated margins and alignment. | Navigation-owned header, section label, and description styles; explanations align with the label column. The Shared space explanation is grouped with and describes its row. | Automated supporting-text and section-label alignment assertions. Passed in Chromium and WebKit (2026-10-19). |
| NAV-03 | Boards, eighteen long shared names and both permission labels at 480px viewport height | Baseline menu had no bounded scrolling body or independently retained header. | Menu viewport bound, scroll body beneath header, wrapping board titles and separate trailing permission slots. | Automated viewport containment, wrapping/metadata separation, End-key scroll and stationary header checks. Passed in Chromium and WebKit (2026-10-19). |
| NAV-04 | Account appearance and actions, More, parent-board list, public-viewer appearance, zoom | Baseline account/viewer/theme rules lived in the global CSS; viewer choices had no visible Appearance section title. Row heights varied by text/padding. | Shared navigation stylesheet with 36px desktop rows, 13px primary text, 12px supporting text, 44px coarse-pointer controls, bounded menu lists, and visible viewer section label. Existing theme and icons preserved. | Browser integration and manual native review to be recorded by the primary reviewer. |

Implemented keyboard behavior is preserved: Boards/ancestor/zoom/viewer Escape restores focus, the Boards close button restores focus, menu arrow/Home/End navigation remains available, and More retains its existing menuitem navigation and canvas-key safety. Tests retain the existing interaction cases in `navigation.spec.ts`.

Local validation: `pnpm --filter web typecheck` passed after implementation and after adding the regression cases. Focused Playwright run: **4/4 passed** across Chromium and WebKit, producing [40 screenshot captures](navigation/contact-sheet.jpg) across five widths and two appearances at 480px height. A representative [populated narrow WebKit capture](navigation/webkit-boards-populated-dark-360.png) was inspected at full resolution; all captures are available for the independent integrated review. The primary workstream owns integrated browser/native verification and final before/after gallery.
