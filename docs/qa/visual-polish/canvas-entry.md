## Independent review RV-02: touch Comments clipping

The reviewer reproduced a 360px touch thread whose left edge was hidden under the creation rail. Before screenshots: [Chromium light](review/chromium-360-light-comments.png), [WebKit dark](review/webkit-360-dark-comments.png). The triggering sequence revealed the trailing Comment action with `scrollIntoViewIfNeeded()` before opening the thread. A hidden-overflow ancestor remains programmatically scrollable, so this could move the stage's origin and consequently shift the complete panel left.

The stage now uses `overflow: clip`, which retains visual clipping while preventing that unintended scrolling. Selection-toolbar horizontal scrolling remains local to the toolbar. Comment textarea focus also uses `preventScroll`. Long author names and timestamps now occupy a flexible metadata column beside independent edit/delete actions; the list scrolls independently of the composer, and touch actions receive 44px targets.

The regression `touch comments preserve the canvas origin and show long author metadata after toolbar scrolling` uses an authenticated account with a long real username, a populated long comment body, a 360px coarse-pointer context and both appearances. It explicitly reproduces toolbar scrolling, checks `stage.scrollLeft === 0`, and verifies the complete heading, author, time, body and close control remain inside panel/canvas bounds. After screenshots are emitted as `comments-touch-long-author-{dark,light}-360.png` by both browser projects. Integrated rerun and visual approval are pending.

## Integrated interaction review

The full suite caught WebKit forwarding the Enter used to choose a search result to the restored breadcrumb button, opening Rename. Fetch now prevents the Enter default before switching boards and restoring focus. The retained cross-board Fetch interaction regression exercises this behavior.
